## 一、 会议总体摘要

本次会议旨在对齐海南城投AI方言交付项目的最新进展与核心挑战。目前项目资金已到位，但面临**客户需求蔓延**与**沟通链路受阻**的双重压力。会议明确了“收敛交付范围、分阶段验证、技术自主兜底”的核心应对策略，决定将交付目标锁定在银行或教育单一场景的智能语音对话系统，并确立了基于阿里生态（Qwen + CosVoice）的技术底座与多渠道数据收集方案。

下文将按照关键决策、风险阻塞、技术实施细节及后续行动计划四个维度展开，重点还原如何在资源受限与需求模糊的情况下，通过工程化手段与数据策略保障项目可交付性。

## 二、 关键决策与待定项

### 关键决策
*   **交付范围收敛**：坚决拒绝全域覆盖，将交付场景收敛至**银行柜面**或**高校图书馆**单一固定场景，优先保证该场景下文昌话ASR（语音识别）与TTS（语音合成）的功能性可用。
*   **技术选型基线**：采用阿里生态组合拳，即 **Qwen-ASR + CosVoice-TTS + Qwen-LLM**。考虑到CosVoice对闽南语系有一定训练基础，优于Qwen-TTS；同时保留FunASR作为备选方案以防微调效果不佳。
*   **交付物形态定义**：交付一套**智能语音对话系统平台**（含API接口与演示端），支持流式交互与RAG知识库问答，而非单纯的翻译机或离线SDK。
*   **商务风控策略**：合同签署采取**分阶段验证**模式，每阶段设定明确验收标准；提前向客户管理预期，明确TTS效果的主观性与创新项目的试错属性，避免过度承诺。
*   **数据资产归属**：明确项目产生的所有语料数据归我方所有，为后续构建自有方言大模型品牌及全国复制奠定基础。

### 待定事项
*   **首选落地场景确认**：需在“银行”与“高校”中二选一。倾向于银行（利于带动自有设备销售），但需评估高校科研配合度及城投方意愿。
*   **语料收集工具开发**：是否投入资源开发微信小程序或有偿众包平台用于自动化采集方言数据，需进一步评估ROI与合规性。
*   **正音词典构建**：文昌话缺乏标准正音词典，需确认是由高校老师主导编写，还是我方通过技术手段并行构建对照表。

## 三、 风险与阻塞点

*   **需求蔓延与认知错位**：客户对AI能力边界认知不足，从最初单一AI算扩展至ASR+TTS+智能对话全套能力，且预算封顶90万。销售端缺乏AI定价概念，导致性价比极低，后续增购可能性小。
*   **“白手套”沟通壁垒**：城投方作为资源整合方（白手套），阻隔了我方与终端用户（高校/银行）的直接技术交流。当前仅能通过文档与中间人传递信息，反馈周期长，技术细节难以对齐，严重影响迭代效率。
    >_【AI 潜台词挖掘】：这种“代理商/白手套”模式是地方国资项目的典型特征。其核心风险在于信息失真与责任隔离——中间人为了促成交易可能过滤掉技术难点，而一旦交付出现问题，我方因缺乏与终端的直接联系，极易陷入“自证清白”的困境。建议务必在合同中约定“关键技术节点需终端用户签字确认”的条款。_
*   **方言数据质量与验证黑箱**：文昌话虽属闽南语系但与主流闽南话差异巨大，且无标准化词典。团队成员听不懂方言，导致TTS效果验证高度依赖主观听感或间接的ASR回测，缺乏客观量化指标，交付验收时极易产生扯皮。
    >_【AI 注释】：TTS（Text-to-Speech）的主观验证难题在小语种/方言项目中尤为突出。MOS（Mean Opinion Score）打分虽为标准方法，但在缺乏母语专家持续参与的情况下，往往流于形式。会议提出的“ASR反向验证TTS”是一种工程化折中方案，即如果ASR能正确识别TTS生成的语音，则证明发音清晰度达标，但这无法保证语调的地道性。_
*   **外部依赖不可控**：高校师生负责语料标注与清洗，但其进度与质量不受我方直接管理。若对方投入度不足或专业性欠缺，将直接导致模型训练失败，而我方目前缺乏并行的自建数据兜底机制。

## 四、 项目讨论详情

### 1. 项目背景与战略价值
*   **商业卡位**：海南自贸港建设背景下，借助中国电子与海南政府的深厚关系，该项目具有极强的战略示范意义。若能跑通“产研结合+方言AI”模式，可快速复制到全国其他方言区，形成公司自有的大模型服务品牌。
*   **国企合作特性**：相比私企，城投等国企更看重资源整合与社会效益，愿意提供稀缺的本地语料与渠道资源。尽管利润空间有限，但其提供的“数据+场景”杠杆价值远超项目本身金额。

### 2. 技术架构与工程化进展
*   **流式对话引擎**：已实现全链路流式传输（ASR -> LLM -> TTS），中间无文本落地延迟。采用 **Qwen-0.6B（前端）+ Qwen-4B-Quant（推理）+ CosVoice（合成）** 的组合，实测响应速度达到感官流畅标准，支持情绪感知与自然打断。
*   **RAG知识库集成**：已完成工行、央行等规章制度文本的导入测试。采用 **PostgreSQL/Redis + 向量库** 的分层检索架构，支持结构化与非结构化数据混合查询。下一步需完善数据清洗、切片工具及前端导入页面。
*   **平台解耦设计**：ASR/TTS微调模块与对话引擎完全解耦。开发人员可独立进行模型训练与验证，无需等待平台整体联调，仅需约定好模型权重或API接口即可并行推进。

### 3. 数据收集与验证策略
*   **多源数据并行**：
    *   **客户侧**：提供标准化录音工具与指定语料文本，要求覆盖不同年龄/性别/音色，避免单一朗读导致的声学单调性。强调高校老师需对语料质量负总责。
    *   **自建侧**：启动网络爬虫（如小红书、本地电视节目字幕）构建基础数据集；探索有偿众包或小程序采集模式，作为质量兜底与长期数据资产沉淀。
*   **验证标准务实化**：不追求99%准确率或完美地道口音，以“功能性可用、听感像样”为阶段性目标。例如，能准确识别并播报几十句银行高频术语，即视为技术路线验证成功。
*   **微调实验计划**：利用现有算力资源，同步尝试Qwen与FunASR的微调效果。鉴于文昌话数据稀缺，小数据量（5-10小时）即可观察到显著变化，需快速试错确定最优基座。

### 4. 团队创新与文化（备注）
*   会议后半段讨论了AI在垂直领域（如乒乓球动作矫正）的创业机会，体现了团队对“小众刚需+技术降维”商业模式的敏锐度。虽非本项目内容，但这种思维模式有助于在海南项目中发掘潜在的衍生产品或服务点。
