# 海南城投文昌话AI交付对齐-AI纪要

## 海南城投项目交付范围与商业约束

- **需求蔓延与预算封顶**
  - 与海南城投秦总完成第三轮交流，资金已到位，但客户需求从初始AI算扩展至ASR、TTS及智能对话三模块打包
  - 90万为当前预算上限，销售团队对AI产品定价缺乏概念，难以追加费用
  - 原计划拆分两期交付（先ASR后TTS），现被客户要求合并实施，TTS翻译难度高且耗时
- **交付场景收敛策略**
  - 客户提及银行、教育、商超等多场景，团队共识需收敛至固定小范围以提升可交付性
  - 发言人1个人倾向优先落地银行柜面业务，认为可带动自有设备收入，但尚未与客户最终确认
  - 教育场景被认为难度过高，若全量覆盖教学则超出当前能力边界
- **合同风险控制机制**
  - 合同将按阶段拆分签署，每阶段设置验证节点，避免最终交付扯皮
  - 明确告知客户TTS效果主观性强，不承诺超越基线模型，丑话说在前头

## 文昌话数据采集与质量保障

- **语料来源三路并行**
  - 高校合作：由秦总协调本地高校师生采集，指定语料、人员及年龄分布（含中老年、儿童），采用朗读方式降低难度
  - 自建采集工具：开发自动化方言收集平台或微信小程序，支持有偿录音，公司已有域名和公众号可快速部署
  - 网络爬取：从小红书等平台抓取文昌话视频字幕，但需注意版权与数据可信度；文昌话全网数据稀缺，重复概率低
- **数据质量控制要点**
  - 强调高校老师须守护语料质量，避免重蹈上海项目因脏数据导致清洗标注浪费时间的覆辙
  - 采集前需自行构建基准数据集，通过电视节目字幕等渠道获取初始语料，用于验证微调效果
  - 不纯依赖外部数据，团队同步自建语料库作为兜底，防止合作方进度不可控
- **正音词典缺失挑战**
  - 海南话缺乏类似上海话的正音词典，仅1968年出版过小词典，需委托高校老师编制对照文档
  - 若无规范对照，TTS输出难以验证准确性，可能需退化为靠近普通话的语义翻译

## 技术选型与架构方案

- **ASR/TTS模型选型争议**
  - ASR初步选用千问，但因闽南语支持有限，发言人1考虑回退至FunASR，担忧LoRA微调易破坏原有性能
  - TTS放弃千问TTS（闽南语知识几乎为零），改用CosVoice，因其训练数据包含闽南语相关语料
  - 两套ASR方案均保留测试，根据现场效果灵活切换，整体未脱离阿里生态
- **智能对话系统架构**
  - 前端使用千问0.6，中间层接入3.5或4B量化小模型，后端CosVoice未量化，全程流式传输无文本中转
  - 响应速度已达可用水平，支持情绪识别与合理打断，工程化细节仍在调优
  - 知识库基于PGVector存储银行规章制度，支持结构化与非结构化检索，页面风格需与龙哥团队对齐
- **平台开发与协作机制**
  - 代码已向团队开放，引擎层封装加密，应用层可自由开发；GPR合并需审核以确保主干稳定
  - 微调与平台解耦，开发人员可先用自研脚本或百炼API验证，后期再对接统一接口
  - 当前平台界面尚未完全跑通，需优先完成本地部署与基础功能联调

## 效果验证与能力边界探索

- **TTS验证方法讨论**
  - MOS打分虽为标准但主观性强，团队对海南话听感陌生，难以独立评判
  - 提议用ASR反向验证TTS输出：若生成的语音能被ASR正确转写为原文，则视为合格
  - 该法只能证伪不能证实，仍需结合人工听感与相似度比对，具体方案未最终确定
- **基础能力验证目标**
  - 在进入海南实地前，需验证ASR/TTS在打招呼、数字播报、银行术语等短句上的表现
  - ASR识别率达80%以上即可接受，TTS能产出1-2个可控短句即证明技术路线可行
  - CosVoice预计5-6小时数据可见初步效果，10小时精标数据可判断方向是否正确
- **长期复用价值判断**
  - 海南项目若走通，可复制至其他方言区，国企产研结合模式适合此类低利润高战略价值项目
  - 语料库与采集工具具备跨项目复用能力，避免重复建设，后续温州话等高难度方言暂不挑战

## 关键决策与共识

- **合同分阶段签署并设验证节点**：接受创新失败可能性，确保每阶段可独立验收
- **语料采集三路并行且不纯依赖外部**：高校合作、自建工具、网络爬取同步推进，团队自主掌握数据主动权
- **技术栈保持灵活性**：ASR/TTS模型可根据实测效果切换，平台与微调解耦以加速验证
